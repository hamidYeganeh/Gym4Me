# Gym4Me — چک‌لیست یوزر استوری × اپ

علائم: ✅ انجام‌شده · 🟡 ناقص (schema / UI mock / API بدون UI) · ❌ شروع‌نشده · — بی‌ربط

ترتیب رفع موارد ناقص، وابستگی‌ها و معیارهای پذیرش در [`cursor-implementation-master-plan.md`](./cursor-implementation-master-plan.md) تعریف شده‌اند. تغییر وضعیت این جدول فقط پس از عبور از Definition of Done همان تسک مجاز است.

> رانتایم فعلی هویت/ادمین/basics/analytics روی MongoDB است. موبایل به API احراز هویت/پروفایل/KYC وصل شده؛ discovery باشگاه/مربی روی API با fallback به mock برای slugهای دمو است.
>
> **Seed دمو:** `npm run db:seed:all -w api` — کاربران همهٔ نقش‌ها (رمز `Gym4Me!123`)، باشگاه‌های تأییدشده/در انتظار/پیش‌نویس، کلاس/سانس، KYC، نظرات و شش صفحهٔ منتشرشدهٔ Discovery با revision اولیه. `db:seed:discovery` مستقل و idempotent است و صفحهٔ دارای محتوای ادمین را overwrite نمی‌کند. تست فلوها: `apps/api/test/smoke-flows.sh` (+ `smoke-booking.sh` / `smoke-membership.sh` / `integrity-flows.sh`) نیازمند API در حال اجرا + `DEBUG_MODE=true`. ادمین به‌صورت پیش‌فرض کلاب‌ها را از API واقعی می‌خواند (`VITE_CLUBS_USE_MOCK=true` فقط برای دموی آفلاین).
>
> **ابزار پایه:** CI (`.github/workflows/ci.yml`: lint + check-types + build api)، `check-types` در api/`@repo/api`، و README بازنویسی‌شده با gates کیفیت و smokes.
